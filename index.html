Plugin for Claude Code, Codex and Cursor

Your coding agent,
held to engineering standards.

Coding agents have two failure modes: they over-build the small thing and under-think the large one. Sinter makes yours size the job before it starts, find the real cause before it patches, and prove the work before it says done.

What changes

Nothing here is a new command you have to remember. These are defaults, they apply to the way you already talk to your agent.

What agents tend to doWhat Sinter does instead
Gives a typo fix the same ceremony as a new service Reads the task, picks a depth, and says which one in a line
Says “fixed” without running anything Every completion claim carries the output of a command that ran
Patches the one call site the ticket named Greps every caller first, then fixes at the root: leaving no siblings broken
Writes a helper the codebase already has Searches for it before writing, and reuses what it finds
Recalls an API signature that changed two majors ago Reads your lockfile, then the docs for that version
Adds a dependency for something the standard library does Works down a ladder: does it need to exist, is it already here, does the platform do it
Quietly turns a one-line request into a 400-line diff Announces the escalation and why, before writing the extra code

It sizes the job first

One router runs before any work and picks a depth lane. Everything downstream: how much gets built, what the test policy is, whether a plan and a human gate are required: follows from that one decision.

LaneForTestsYou get
lazyOne file, a known fix One runnable check if the logic is non-trivialCode, then three lines
standardA feature, several files, a new dependency Red/green TDDThe complete change, plus the tradeoffs
fullA new system, a spec, a migration TDD, behavioural verification, quality gatesA plan you approve before code exists

Try it. Describe a task the way you would to your agent. This runs the same rules the router uses.

Notice what the second example does. It reads as a small job, but it touches authentication, so the lane goes up, and Sinter tells you rather than quietly doing more work than you asked for.

Five rules it will not bend

No lane, setting, or instruction relaxes these. They are the reason the rest holds together.

01
Read before you write

Trace the real flow first. A small diff in the wrong place is a second bug.

02
Cause, not symptom

Find why it happens and fix it where every caller passes through.

03
Say what you actually did

Ran it, reviewed it, expect it to work, or assumed it: always marked.

04
Some things never get cut

Input validation, error handling that prevents data loss, security, accessibility.

05
Evidence before done

“Done” is a claim about the world. It needs output you read.

Where it comes from

Sinter is the metallurgical process that fuses separate particles into one solid mass under heat and pressure, without melting away what each one was. The plugin is built the same way.

Eight open-source methodologies each solve one part of this well. Installed together they collide, three try to own how verbose your agent is, two try to own its test policy, two try to own its plan format. You end up arbitrating conflicts your tools should have settled. Sinter settles all nine, once, at design time.
